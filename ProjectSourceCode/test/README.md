# Registration Testing

## Registration Contract

### Endpoint

`POST /login/register`

### Request format

HTML form submission (`application/x-www-form-urlencoded`).

### Required fields

| Field | Requirements |
|---|---|
| username | 2–64 characters |
| email | Valid email format, maximum 200 characters |
| password | At least 8 characters |
| confirmPassword | Must match password |

### Successful registration

- HTTP status: `302`
- Redirect location: `/login?registered=1`
- Creates exactly one record in the `users` table.
- Password is stored as a bcrypt hash in `password_hash`.

### Invalid registration

- HTTP status: `400`
- Renders the registration page with an error message.
- Missing password returns: `Password must be at least 8 characters.`
- No user record is inserted.

### Duplicate registration

- HTTP status: `409`
- Renders the registration page with an error message.

### Database persistence

The registration route inserts the following columns into `users`:

- `username`
- `email`
- `password_hash`

The `user_id` and `created_at` columns are generated by the database.

## Test Organization

- `validation.spec.js`: Unit tests for registration input validation.
- `server.spec.js`: HTTP integration tests for registration and the welcome route.

## Test Setup

Tests use the separate PostgreSQL test database configured through `test.env`.

Run the test suite using the project's test Docker Compose configuration:

```bash
docker compose -f docker-compose.test.yml up --build
```

## Cleanup

Registration integration tests generate unique usernames and email addresses using UUIDs.

Test users are deleted before and after each registration test. This prevents test records from accumulating and allows the test suite to run repeatedly.

The PostgreSQL connection pool is closed after the test process finishes.
